# 场景布景

按景观主题组织，与车辆、玩家和玩法道具分开：

- `meadow/Meadow.js`：现有乡野景观，包含树、灌木、树篱、草垛、石头、花桶及路牌。当前仍使用程序生成占位模型。
- 后续城市主题放入 `city/`，其他主题各自建目录；没有城市资源时不创建空实现。
- `SceneryChunks.js`：主题间可复用的循环道路静态合批器。
- 原 `world/Props.js` 保留为 Meadow 的兼容入口，当前场景调用方式不变。

## 替换正式资源

模型生成和摆放规则放在对应主题内。替换 meadow 的模型时，保持现有道路参数（循环长度、随机种子）与主题边界；加载应走 SceneReadiness，在启动或黑屏内完成，游玩时不加载或重建。

当前合批器接受单材质、无独立动画的静态 Mesh，按材质、阴影和 layer 分组，沿道路约每 20 米以及横向每 20 米划块。保留原几何体、法线、顶点色和描边；动态摆件、透明或多材质正式资源应按其要求单独组织，不能直接套用自然布景的合批输入。路牌目前单独滚动绘制。

每个区块的三个相邻周期副本共享几何体和材质，仅移动区块的 x；远处副本由主相机和阴影相机独立裁剪。这样道路循环接缝连续，且不需要每帧上传顶点。合并后的包围盒和球在启动时计算，参与已有的画面及阴影预热。

本模块是客户端视觉布景，不产生碰撞、订单或权威状态；未来会影响玩家/车辆的障碍规则须另在 shared 实现并同步服务器。
